Date: 2026-05-16

## Goal

先把 LEAD 官方 checkpoint 用 LEAD repo 自己的 NAVSIM evaluation code 跑通 navtest PDM，拿到一个可信的 official baseline。这样可以排除我们 MoT-DP 侧 wrapper、image preprocessing、trajectory decode 或 metric 调用写错导致的干扰。

## Stage 3: Official LEAD vs MoT-DP Agent Parity

Only after official LEAD score is available, build a parity/debug tool. Suggested path:

`tools/compare_lead_navsim_preprocess.py`

Use the same navtest tokens for both official LEAD and our agent, preferably:

- a few normal high-score scenes,
- a few turning scenes,
- several MoT-DP DAC=0 bad cases from the cached full result.

Dump and compare:

- raw stitched image from official `TransfuserFeatureBuilder`,
- image generated by `OnlineLeadDiffusionAgent._build_lead_input`,
- JPEG compression/decompression behavior,
- image shape and dtype,
- BGR/RGB channel order,
- crop policy,
- resize policy: whole stitched image resize vs per-camera resize,
- CHW tensor min/max/mean/std,
- LEAD BEV feature stats,
- LEAD waypoint output,
- final trajectory after y/headings conversion.

High-risk differences to inspect first:

- Official NAVSIM feature builder stitches `[l0, f0, r0, b0]`, resizes whole stitched image by `/4`, then JPEG-compresses at quality 30 before agent decode。
- Our current online agent crops each camera with `img[10:-10]`, resizes each camera to `(480, 270)`, then concatenates. This may not be identical to the official NAVSIM feature path.
- Official `CarlaTransfuserAgent` decodes `camera_feature` with `cv2.IMREAD_COLOR`, transposes HWC to CHW, then forwards through `OpenLoopInference`.
- Official output flips waypoint y and heading sign for NAVSIM.

## Stage 4: Patch Policy

Do not modify `OnlineLeadDiffusionAgent` until parity identifies a concrete mismatch.

Patch order:

1. If image pipeline differs, make our online agent reuse the official NAVSIM `TransfuserFeatureBuilder` camera path or match it byte-for-byte.
2. If BEV differs after image parity is fixed, compare LEAD `load_tf` shortcut against official `OpenLoopInference` model construction.
3. If BEV matches but trajectory differs, inspect diffusion trajectory coordinates, y flip, heading construction, and smoothing.
4. If pure official LEAD is also unexpectedly low, pause agent changes and verify checkpoint, config, and NAVSIM metric version.



## How We Did It

This is the canonical reproduction path for the current LEAD official NAVSIM validation attempt.

1. We use LEAD repo code as the trusted source for the official checkpoint path.
   - LEAD repo: `/workspace1/z_project/code/lead`
   - Vendored NAVSIM devkit: `/workspace1/z_project/code/lead/3rd_party/navsim_workspace/navsimv1.1`
   - Official NAVSIM agent config: `agent=carla_transfuser_agent`
   - Official checkpoint: `/workspace1/z_project/models/navsim_backbones/tfv6_navsim/model_0060.pth`

2. We do not use LEADs `evaluate_navtest` helper directly.
   - The checkout references `slurm/evaluate_navtest.sh`, but that file is missing.
   - Instead, we call LEADs vendored NAVSIM scorer directly through `run_pdm_score.py`, matching the intent of LEADs `run_carla_transfuser.sh` path.

3. We create a runtime checkpoint directory instead of modifying the official checkpoint.
   - Reason: LEADs `TrainingConfig` can evaluate properties before `use_navsim_data=true` is applied from the checkpoint JSON.
   - Runtime directory: `/workspace2/z_project/navsim_exp_lead_official/checkpoints/tfv6_navsim_model0060_config_ordered`
   - The script symlinks `model_0060.pth` and writes a reordered `config.json` with NAVSIM switches first.
   - The original checkpoint and original `config.json` remain untouched.

4. We build a LEAD-compatible NAVSIM v1.1 metric cache.
   - Existing cache `/workspace2/data/navsim/processed_data/metric_cache_navtest` is a newer NAVSIM cache and failed in LEAD v1.1 with a `SceneFrameType` pickle mismatch.
   - Therefore the canonical cache path for official LEAD v1.1 is now:
     `/workspace2/z_project/navsim_exp_lead_official/metric_cache_navtest_v1_1`
   - Script: `/workspace1/z_project/code/motdp_z_navsim_motdp/scripts/_run_lead_official_navtest_cache.sh`

5. We run official LEAD evaluation only after the matching v1.1 cache exists.
   - Script: `/workspace1/z_project/code/motdp_z_navsim_motdp/scripts/_run_lead_official_navtest.sh`
   - Smoke command:

```bash

GPU_ID=2 MODE=smoke EXPERIMENT_NAME=lead_official_navtest_smoke16_model0060_20260516_v1cache scripts/_run_lead_official_navtest.sh
```

6. Full navtest is chained through a tmux driver.
   - Tmux session: `lead_navtest_full_0516`
   - Driver: `/workspace2/z_project/navsim_exp_lead_official/run_full_20260516.sh`
   - The driver first builds full v1.1 metric cache with `WORKERS=8`, then runs full official LEAD eval with `WORKERS=1` and `GPU_ID=2`.
   - Cache log: `/workspace2/z_project/navsim_exp_lead_official/logs/lead_navtest_full_cache_20260516.log`
   - Eval log: `/workspace2/z_project/navsim_exp_lead_official/logs/lead_navtest_full_eval_20260516.log`
